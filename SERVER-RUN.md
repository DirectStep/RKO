Кабинет сохраняет адрес `https://app.xn--j1aalbgc.xn--p1ai` (`app.ркорко.рф`).
В Cloudflare настроена A-запись app → 89.111.173.217 с DNS only.
HTTPS-сертификат Let's Encrypt выпущен; цепочка и имя проверены с внешнего

На сервере работают PostgreSQL, приложение с двумя ботами и Caddy.
Docker запускается автоматически, контейнеры используют `unless-stopped`.
База не опубликована в интернет; порт 8090 доступен только с самого сервера.
Открыты TCP 22, 80, 443. Установлен swap 1 ГБ. Включён production-режим;
локальная авторизация администратора отключена.

Проверки после переключения DNS: публичная главная страница возвращает 200,
`/api/session` без подписи Telegram — 401, с корректными подписями каждого из
двух ботов `/api/session` и `/api/dashboard` возвращают 200. В серверных логах
подтверждены два polling, обновления Google Sheets, ставок и условий банков,
без ошибок и конфликтов polling на момент проверки. Открытие кнопки внутри
пользовательского приложения Telegram требует отдельной ручной проверки.

`rko-backup.timer` ежедневно около 03:00 МСК делает копию базы в `/var/backups/rko`.
Проверено восстановление автоматической копии в отдельную тестовую базу.
Копии на VPS не заменяют отдельную внешнюю копию.

Локальная база оставлена для восстановления; локальные bot и tunnel остановлены,
их автоматический перезапуск отключён. Файл `secrets/production-server.active`
блокирует запуск через Start-RKO.cmd. Не запускайте старые контейнеры вручную
из Docker Desktop: это создаст второй polling и синхронизацию устаревшей базы.
Для возвращения на ноутбук сначала остановите серверного бота, сохраните и
перенесите свежую серверную базу, восстановите туннель и только после этого
снимайте локальную блокировку. Старого токена туннеля на ноутбуке сейчас нет.
